# План: русская локаль (вариант C) — по фазам

Цель: добавить полноценную русскоязычную версию сайта с `hreflang`, **не ломая**
существующую украинскую версию и её позиции в Google. Каждая фаза самодостаточна
и отгружаема (сайт остаётся рабочим после любой из них).

> Контекст: сайт на Next.js 14 App Router, сейчас украиноязычный (моно). UA —
> приоритетная локаль. Русская версия — дополнительная, под запросы вроде
> «купить бутсы» от пользователей из Украины.

---

## Ключевые архитектурные решения (утвердить перед стартом)

1. **URL-стратегия: UA остаётся на корне, RU под префиксом `/ru`.**
   - `/catalog/butsy` — украинская (URL не меняется → позиции сохраняются);
   - `/ru/catalog/butsy` — русская.
   - Причина: любое изменение существующих UA-URL = риск потери рейтинга.
     RU добавляется **аддитивно**.

2. **Механизм i18n: сегмент `app/[locale]/…` + middleware «prefix-as-needed».**
   - Все страницы переезжают под `app/[locale]/`.
   - Middleware: запрос без префикса → внутренний rewrite на `uk` (URL остаётся
     чистым, без `/uk`); `/ru/*` → локаль `ru`.
   - Без внешних зависимостей (лёгкий кастомный словарь). Альтернатива —
     `next-intl`, но добавляет зависимость и конфиг; для сайта такого размера
     достаточно кастома.

3. **Товарные данные (названия, страна) — из Google Sheets на украинском.**
   Автоперевод не делаем: бренд и модель (Nike Mercurial, Adidas) — языконезависимы.
   Слово-категория в начале названия («Бутси…») остаётся украинским.
   Возможная опция на будущее: RU-синонимы в keywords карточки. **Ограничение
   задокументировано, решаем отдельно.**

4. **hreflang:** на каждой странице `alternates.languages`:
   `uk-UA` → UA-URL, `ru-UA` → RU-URL, `x-default` → UA-URL; canonical → на себя.

## Фаза 1 — Фундамент i18n и роутинг (UA не меняется)

**Задачи:**
- `lib/i18n.ts`: `type Locale = 'uk' | 'ru'`, `LOCALES`, `defaultLocale = 'uk'`,
  `isLocale()`, `localizedPath(locale, path)`, `hreflangAlternates(path)`.
- Словари: `lib/dictionaries/uk.ts` (заполнить текущими строками) и `ru.ts`
  (клон uk как заглушка — переведём в фазах 2-3). Тип `Dictionary`.
- **Перенос страниц** под `app/[locale]/…` (механически, все существующие
  страницы). `generateStaticParams` → `[{locale:'uk'},{locale:'ru'}]`.
- `middleware.ts`: rewrite корня на `uk` (без изменения URL), обработка `/ru`.
- Прокинуть `locale` из params в компоненты (пропом или через контекст).
- Метаданные: добавить `alternates.languages` + canonical в layout/страницы.
- `robots.ts`: разрешить `/ru`.

**Deliverable:** UA работает как раньше (URL не изменились, все страницы 200);
`/ru/*` открывается и рендерит UA-плейсхолдер-текст; hreflang присутствует.

**Проверка:** все прежние UA-URL отдают 200 и прежний контент; `/ru/catalog/butsy`
открывается; в `<head>` есть корректные hreflang и canonical.

**Риск:** самый рискованный шаг — перенос всех роутов. Тщательно сверить, что ни
один UA-URL не изменился и не сломался.

## Фаза 2 — Перевод интерфейса (RU)

**Задачи:**
- Заполнить `ru.ts` для всей «обвязки»: шапка (навигация, плейсхолдер поиска),
  фильтры `CatalogBrowser` (много строк: «Вид товару», «Бренд», «Модель»,
  «Розмір», «Ціна», заголовки групп), сортировка, кнопки товара («Оберіть розмір»,
  «Додати в кошик»), корзина, чекаут (поля формы, Нова Пошта), избранное, подвал,
  «хлебные крошки», пагинация.
- Заменить захардкоженные UA-строки в компонентах на `t(dict, 'key')`.
- Числа/даты — локаль-зависимый формат (`toLocaleString('ru-UA')` для RU).

**Deliverable:** `/ru` — русский интерфейс; данные товара пока на украинском.

**Проверка:** пройти по `/ru` каталог → карточка → корзина → чекаут: вся обвязка
на русском, функции работают.

**Deliverable:** `/ru` полностью на русском для авторского контента сайта.

**Проверка:** инфостраницы, категории и статьи на `/ru` — на русском; UA-версии
не затронуты.

## Фаза 4 — Метатеги, hreflang, sitemap, переключатель, полировка

**Задачи:**
- Локаль-специфичные `title`/`description` (RU-копирайт) на всех ключевых
  страницах.
- **Переключатель языка** в шапке (и подвале): сохраняет текущий путь, меняет
  локаль (UA ⇄ RU).
- `sitemap.ts`: отдавать URL для обеих локалей + `alternates` (hreflang) в записях.
- OpenGraph `locale` + `alternateLocale`.
- (Опция) RU-синонимы в keywords карточки товара для семантики поиска.
- Финальная сверка hreflang по всем типам страниц (главная, каталог, категория,
  бренд, товар, блог, инфо).

**Deliverable:** полноценная двуязычная версия с корректным SEO для обеих локалей.

**Проверка:** на любой странице есть пара UA/RU + hreflang + x-default;
переключатель работает и сохраняет путь; sitemap содержит обе локали.

## Оценка объёма
- Фаза 1 — средняя (структурный перенос + middleware + hreflang-скелет).
- Фаза 2 — средняя/большая (много строк интерфейса, особенно фильтры).
- Фаза 3 — средняя (перевод текстов, включая 3 статьи).
- Фаза 4 — небольшая/средняя (метатеги, переключатель, sitemap).

Рекомендация: за один заход в свежем окне — минимум **одна фаза целиком**
(лучше 1, т.к. она разблокирует остальные). Фазы 2-4 можно дробить свободно.
